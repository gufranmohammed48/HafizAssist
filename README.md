# HafizAssist

A browser-based Quran memorization companion. Read a selected passage, recite into your microphone, and follow approximate word-level matching. The model runs locally in a Web Worker using Sherpa ONNX WebAssembly. Audio is neither recorded to disk nor sent to a server.

## Run locally

Use Python 3 with `py scripts/serve.py` (or `python scripts/serve.py`). This launcher serves both the project files and the public asset folder; plain `python -m http.server` from the repository root does not provide that mapping. No packages need to be installed. Open http://localhost:5173 or http://localhost:5173/mobile.html and leave the terminal open. Press Ctrl+C to stop.

Alternatively, use Node.js 20.11 or newer. There are no npm dependencies to install.

```powershell
node scripts/serve.mjs
```

Open **http://localhost:5173**. Do not open `index.html` directly: microphone capture, modules, and the speech worker require a local server or HTTPS.

1. Use the single search field: `4` opens page 4, `s 2` opens chapter 2, `2:255` opens that verse, and `Yasin` or `يس` opens Ya-Sin. The adjacent dropdown lists each surah number with its English and Arabic names. Page arrows move through all 604 pages.
2. Press the microphone button once. It loads the model and continues directly into microphone setup.
3. Allow microphone access. The first model download can take a while; subsequent visits open the saved copy and initialize the engine again without downloading the weights.
4. Recite the selected passage. Green means a phonetic match; amber means a word to review, not a proven mistake.
5. Stop to pause and save a local session summary. Click a Quran word to hear its reference recording; this leaves your reading position and results unchanged. **Reset** clears the current session, not history.

The main controls are microphone, Teacher, show/hide, search, and settings. Open the Teacher panel and turn Teacher on for a one-word hint after five seconds of quiet and immediate reference playback when tracking flags a word for review. Both behaviors use the same Teacher toggle. The magnifying-glass button opens **Find a verse** for voice search. Settings contains text search, the surah dropdown, reset, and appearance options. Desktop controls sit beside the centered book when its actual left gutter has room; otherwise they form a row above the page. Mobile uses five 44-pixel touch buttons above the page. Local previews and test pages show the loaded version badge at the far right; production desktop/mobile builds place the account icon there and hide the badge. The upper-right Mushaf label shows the Juz with its Arabic ordinal name, such as `الجزء الأول`; page navigation remains centered above the text.

The eye button hides or shows all Quran words, including matched words, without interrupting tracking. Hidden words are blank, without placeholder lines, while verse numbers remain visible on all four pages. Light/dark themes, automatic following, and the last 30 session summaries are implemented. Matching uses the Balanced preset. The microphone stops when the tab is hidden or the page closes.

Revised recognition hypotheses cannot rewind the live cursor or completed word highlights. With Teacher enabled, the first newly flagged mistake holds the pointer at that word on all four pages, before later words receive highlights. Teacher plays its reference, then the learner must match that word with fresh speech before continuing to the next word. Its original error mark and mistake count remain; a successful retry does not count it twice. Queued learner results, Teacher audio, and its echo cannot satisfy the retry or complete later words. Manual word playback and pause hints do not start this correction hold. To revisit other earlier words deliberately, stop and reset or choose another passage.

## Offline use

Open the page once while the local server is running (or visit an HTTPS deployment while connected). The service worker saves the complete application, all Quran data, the font, token table, audio worklet, and Sherpa JS/WASM runtime. Load the model once with **Start reciting**, or select the downloaded INT8 file when prompted.

Wait until the status beneath the recorder says **Ready offline**. After that, reopen the same URL in the same browser/profile to read and recite without an internet connection. A loaded model alone is not enough: the app/runtime files must also finish caching. No recording needs to be made to prepare offline use.

If storage is blocked, full, cleared, or later evicted by the browser, offline assets may need to be saved again. Offline readiness is checked at startup, after model loading, and when returning to the page. The page distinguishes a saved app from a missing model instead of claiming full offline readiness prematurely.

Updates are downloaded in the background and activated after all HafizAssist tabs are closed, avoiding a runtime change mid-recitation. Close all its tabs and reopen when the update message appears. Developers must bump `VERSION` in `public/sw.js` whenever shipping changes to cached files. Service worker behavior follows the [MDN lifecycle documentation](https://developer.mozilla.org/en-US/docs/Web/API/Service_Worker_API/Using_Service_Workers).

## Architecture

- `src/app.js`: passage selection, Quran rendering, capture lifecycle, history, UI state.
- `src/alignment.js`: weighted semi-global phoneme alignment, free-start recovery past extra speech, connected-word matching, revised partial hypotheses, and supported lookahead before marking skipped words.
- `src/vowel-feedback.js`: test-page post-match vowel comparison for supported substitutions, additions, and omissions; production retains its existing review path.
- `src/tajweed-timing.js`: test-page duration thresholds and separate suggestions from available recognition timing; insufficient evidence remains ungraded.
- `src/tajweed-log.js`: test-page bounded, in-memory diagnostic history and manual JSON export; no audio recording or upload.
- `src/tajweed-colors.js` and `public/data/tajweed-colors.json`: test-page optional letter colouring from conservatively mapped Quran Foundation annotations, bundled for offline use.
- `scripts/import-tajweed-colors.py`: imports tagged Uthmani Tajweed source text into spans against the existing Quran words without modifying their text.
- `src/recognition-boundary.js`: consumes token timestamps to preserve progress when earlier recognition text changes.
- `src/book.js` and `src/book.css`: shared book interface, search/settings drawers, and floating controls for desktop, mobile, and the preview entry.
- `src/teacher-mode.js`: reference word audio, bounded clip cache, quiet-time hints, review prompts, word-click playback, and playback cancellation on the book interface.
- `src/teacher-voices.js`: shared Teacher side panel and voice choices on desktop, mobile, and the test entry.
- `src/teacher-activity.js`: sustained floating-point PCM activity with an adaptive ambient baseline, supplemented by recognition changes, for Teacher pause scheduling.
- `public/audio-worklet.js`: continuous microphone resampling to 16 kHz mono PCM in 320 ms chunks.
- `public/recognizer-worker.js`: model loading/cache, speech segments, Sherpa inference, bounded processing backlog.
- `public/data/quran.json`: canonical per-word phonemes and HafsSmart glyph text for all 114 surahs.
- `public/data/mushaf-layout.json`: bundled Quran.com page/line metadata for all 6,236 verses. Each verse key maps to `[juz, [[page, line], ...]]`, including its ending ayah marker. Four combined Quran.com words are split to match the existing phoneme dataset; see the attribution notice.
- `public/assets/bismillah.png`: header artwork copied from the owner's Desktop-HafizAssist project.
- `public/vendor`: the reference project's compatible Sherpa JS/WASM bundle.
- `public/sw.js` and `src/offline.js`: versioned offline application cache and readiness messages; the model cache is preserved across application upgrades.

The tracker preserves repeated phonetic symbols and gives elongation/gemination differences a reduced matching cost. It does **not** grade madd duration, tajweed, pronunciation correctness, or memorization accuracy. Green is an approximate alignment result. Weighted costs and sequence handling are adapted from the reference project's approach, not a complete port of its engine. Unmatched phonemes are carried across automatic recognition endpoints; starting a new microphone session clears that carry. Longer mistakes, repeated phrases, a start far from the chosen word, background speech, or difficult microphones may still cause tracking to stall or drift. Stop and select the correct word to resume. The model author also documents limitations on children’s recitation and tajweed distinctions.

Automatic tracking can be wrong. Automatic tajweed feedback can be wrong and does not replace a qualified teacher.

## Tracking recovery and teacher design (V53)

Source inspection found several causes of repeated-word stalls: the preview's final-vowel wait had no callback for an unchanged but settled hypothesis, vowel differences could reject a short word before the review verdict was produced, recovery looked only two words ahead, and a revised consumed text prefix could send alignment back to a previously completed word.

The worker now sends one settled snapshot after at least 640 ms of unchanged recognized text and quiet captured audio. This can release the experimental vowel-ending wait without treating the snapshot as an endpoint or bypassing the missing-core-sound guard. Short-vowel substitutions in the preview can advance tracking while remaining marked for review. When progress has stalled for at least 1.8 seconds, additional recovery can inspect up to six following words in the same ayah, requiring two or three strong consecutive matches and rejecting identical recovery phrases elsewhere in that window. Missing words remain review items; elapsed time alone never passes a word.

Token timestamps now accompany recognition results on all layouts. Consumed boundaries can be relocated by token time after earlier text revisions, including across page turns. An unrelocatable boundary waits for a fresh segment instead of replaying completed speech. The cursor remains forward-only. These source changes address specific blocking paths; model uncertainty, background noise, and ambiguous passages can still prevent a confident match.

Teacher mode is documented in [the design](docs/TEACHER-MODE.md), with a separate [interactive layout proposal](docs/teacher-mode-preview.html). It is not connected to live recitation or audio playback yet. The proposal uses human Quran recordings with the existing recognition model, a five-second quiet-time hint, correction after a pause, manual replay, and explicit audio downloads for offline use. Reference playback must be excluded from recognition and grading. No tests, builds, browser checks, or microphone tests were run for V53.

## Functional Teacher audio (V54)

Open `/test.html` and use Settings → Teacher → Enable teacher. Hear this word works manually even when the automatic teacher is off. During recitation, five seconds of quiet requests the next unread word once. A recent word flagged for review can be replayed after a 1.2-second quiet pause; continuing more than six words beyond the flag cancels that queued review. The feedback card has Replay word and Dismiss. Audio does not regrade an error, advance the cursor, or certify pronunciation/Tajweed correctness.

Reference clips come from Quran.com's public word-audio CDN. Inserted Bismillah and the four source words split by the phoneme dataset have explicit audio-position mappings. Up to three upcoming clips are prefetched when Teacher is enabled. Downloaded clips are cached separately from the model for up to six days, with a maximum of 200 retained clips. Direct media streaming is a fallback if readable downloads fail; that fallback is online only. This is not a full offline Quran audio pack. See [Teacher mode](docs/TEACHER-MODE.md) for source and caching details.

Capture buffering is paused and discarded before playback, outstanding recognition results are excluded, and a fresh recognition session starts at the unchanged cursor. Capture resumes after a 400 ms echo tail. Cancellation, failed downloads, missing recordings, blocked audio, and playback timeouts restore listening. No tests, builds, browser checks, or microphone tests were run for V54.

## Teacher pause scheduling (V55)

V54 required an exactly empty inference queue at the instant its timer polled, even though capture continuously enqueues silence. It also restarted the pause clock on every small microphone RMS/peak crossing. V55 accepts a healthy bounded backlog, pauses PCM submission, and drains already queued learner results before resetting recognition. If those results change the reading position, a stale prompt is cancelled. Reference playback remains excluded from recognition and counts.

Teacher scheduling now observes sustained float PCM energy with an adaptive ambient baseline and independent recognized-sound updates; the analyser only animates the mic. This is a heuristic, not a separate voice model, and background speech or unusual microphones may still resemble recitation. A countdown appears after one quiet second; Settings reports whether Teacher is listening or waiting for recognition to catch up. Teacher options are hidden while its master switch is off. Feedback appears above a modal Settings drawer. Cancelled review prompts remain eligible for the next pause; an audio failure gets one delayed retry, then offers manual replay instead of looping. No tests, builds, browser checks, or microphone tests were run for V55.
